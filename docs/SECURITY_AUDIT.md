# Open-source release audit (v1.0.0)

Audit of the repository, its complete Git history and the application before publication. Performed by the builder
on 2026-10-24; independently reviewed as recorded in `docs/review-ledger.md`.

## 1. Secrets and credentials

| Check | Method | Result |
|---|---|---|
| Full history (all commits, all refs) | `gitleaks git` v8.30.1 (official image) | no leaks |
| Working tree incl. build output | `gitleaks dir` | no leaks |
| Additional patterns (AWS/GitHub/OpenAI/Slack tokens, private keys, JWTs, `password=`/`token=` literals) | `git log --all -p` + regex | none |
| Credential / key files ever committed (`*.p12 *.pem *.key *.cer *.mobileprovision .env*`) | `git log --all --name-only` | none |

No secret was ever committed, so no rotation was required. CI scans every push and pull request with gitleaks
(pinned version, checksum-verified binary).

## 2. Personal information

| Finding | Severity | Remediation |
|---|---|---|
| Commit author/committer emails contained the local account name and machine hostnames | medium (privacy) | History rewritten for publication to the owner's GitHub noreply identity (owner-approved). Original commits kept only under local backup refs, never pushed. |
| Committed build logs (`evidence/latest/*.log`) contained the absolute home-directory path | low (privacy) | Paths rewritten to `.`/`~` in every historical commit during the rewrite; `scripts/collect_evidence.sh` now sanitises logs. |
| Work-hour databases, backups, Keychain data | — | Never committed. `.gitignore` now blocks `*.sqlite*`, `*.db`, `Backups/`, signing material and `.env` files. |
| Screenshots | — | Rendered from deterministic demo data (`Workday --snapshot`), not real usage. |

Verification after the rewrite: `git log --all --format='%an %ae %cn %ce'` on the published refs shows only the
noreply identity, and `git grep` across all published commits finds no home-directory path (see review ledger).

## 3. Machine-specific configuration

`Package.swift` and `scripts/test.sh` reference the standard Command Line Tools location
(`/Library/Developer/CommandLineTools`) only to locate Swift Testing when Xcode is absent; this is generic, not
user-specific. No other absolute paths or private configuration are present.

## 4. Development artefacts and binaries

* `dist/`, `.build/`, DerivedData are ignored.
* Committed binaries: `Resources/AppIcon.icns` (generated by `scripts/make_icon.swift`), evidence and README PNGs
  (rendered by the app). All are original works of this project.
* Evidence logs, perf results and review records are kept intentionally as verification records.

## 5. Dependencies and licensing

* **No third-party packages** (`scripts/check_dependencies.sh` enforces this in CI). System frameworks only:
  AppKit, SwiftUI, Observation, SQLite3, ServiceManagement, UserNotifications. Hence no dependency
  vulnerabilities to track; Dependabot watches the GitHub Actions used by CI.
* All source code, scripts, the icon and documentation were written for this project → **MIT licence** is
  compatible.
* **SF Symbols** are referenced by name and rendered by macOS at runtime; they are not redistributed. Apple's
  licence permits their use in apps' user interfaces on Apple platforms.
* Fonts: system fonts only, nothing bundled.
* `docs/SPEC.md` is the owner's original product specification, published under the same licence.

## 6. Application security review

| Area | Finding | Status |
|---|---|---|
| Network | No networking code; no entitlements; hardened runtime enabled | OK |
| SQL | All statements use bound parameters; schema constraints (`CHECK end > start`) | OK |
| File permissions | Data folder and database were created 0755/0644 (protected only by the 0700 parent `Application Support`) | **Fixed**: 0700 directories, 0600 database/backups (test `ownerOnlyPermissions`) |
| Backups | Created via SQLite online backup API, validated before use; corrupt files refused | OK |
| Inter-process | A `DistributedNotificationCenter` message can ask a running Workday to show its calendar | Accepted: only opens a window, no data or actions exposed |
| Developer switches | `--seed-demo`, `--perf` require `WORKDAY_DATA_DIR` (never touch real data); `--snapshot`/`--benchmark` use temporary data | OK |
| Single instance | `flock` on a lock file in the data folder | OK |
| App Sandbox | Not enabled (Developer ID distribution doesn't require it; enabling it would move user data into a container and break existing installs) | Documented |

## 7. GitHub Actions

* Default `permissions: contents: read`; only the release job that creates a draft release gets `contents: write`.
* No secrets are referenced by any workflow; `pull_request` (not `pull_request_target`) is used, so fork PRs run
  without secrets and with a read-only token.
* Third-party actions pinned to full commit SHAs; `persist-credentials: false` on checkout.
* Releases are created as drafts — publication is a manual owner step.
